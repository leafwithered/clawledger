# Real ZeroClaw runtime validation

Validation date: 2026-08-01 (Asia/Shanghai)

This test used the official ZeroClaw v0.8.3 Windows binary and a real model
turn. It was not a mocked shell transcript. Authentication, the raw runtime
trace, and agent state remain under the ignored `.tools/` directory and are
not part of the repository.

## Safety boundary exercised

The agent ran with a supervised, workspace-only risk profile. Delegation was
disabled, the available command surface was limited to Python, and the agent
could use only shell and SOP control tools. Tool receipts were enabled.

ZeroClaw correctly rejected initial attempts to use `python -m` and
`python -c` under its interpreter policy. The Skill was then narrowed to one
reviewed script with fixed imports:

```text
zeroclaw/skills/clawledger/scripts/clawledger_cli.py
```

No policy bypass was added. The reviewed script became the allowed execution
path, and the stock Skill audit passed with four files scanned.

## Real checkpoint result

The agent loaded the ClawLedger Skill and checkpointed its own information-level
`runtime-trace.jsonl`. An independent process then verified the manifest:

```json
{
  "valid": true,
  "reason": "ok",
  "expected_root": "54359cb618358a6bf58c32d20dc5ccffa52f405f4539485521e2936851e0757f",
  "actual_root": "54359cb618358a6bf58c32d20dc5ccffa52f405f4539485521e2936851e0757f",
  "event_count": 64
}
```

A second real ZeroClaw agent turn invoked only the reviewed verification
command. It returned the same result and exposed the shell result as a tool
receipt. This closes the loop between the agent-visible result and independent
verification without publishing any raw event content.

The finalized-anchor decoder was also hardened after this run: it accepts only
the exact one-signature, two-account, one-Memo transaction shape generated by
the Action and rejects extra instructions or trailing bytes. Those negative
cases are covered by the automated suite.

## Deliberately excluded

- The raw trace can contain prompts, tool arguments, and local paths.
- Local model authentication and encrypted ZeroClaw state are not publishable.
- A wallet-signed devnet anchor still requires explicit operator approval.
- A Telegram or Discord bot token and account binding still require the
  operator; the CLI run proves the runtime integration but is not a substitute
  for the final real-channel demo.
